## 🔴 HIGH RISK: Model/Data Behavior Changes

These changes alter either the data-generating process or the training numerics. Any one of them could explain broken training.

### 1. `FrozenRandomMLP` hidden_dim change for `nd-kf-mlp`

| Commit | File |
|---|---|
| `cf3ddcc` (Jun 5) | `dataset.py` — modularize init |
| Current HEAD | `dataset.py` — `_init_nd_kf_mlp` |

**What changed:** Old code used `hidden_dim=64` (hardcoded default). New code computes `hidden_dim = max(in_dim, self.d_out)`. For B13-style configs (`k_shared=2, m_unique=2, d_out=16`): `hidden_dim` goes from **64 → 16**.

**Impact:** Completely different MLP architecture → different manifold geometry → model trained on old manifold sees entirely different data.

**Verdict:** 🔴 REVERT to `hidden_dim=64` default for backward-compatible behavior, or make it a config parameter.

### 3. Pre-MLP noise vs Post-MLP noise (`nd-kf-mlp`)

| Commit | File |
|---|---|
| Introduced during refactor sequence (cf3ddcc/46d0c46) | `dataset.py` |

**What changed:** Old code added manifold noise to MLP **outputs** (observation space noise). New code adds noise to MLP **inputs** (latent space perturbation before MLP transform). These are fundamentally different noise models:
- **Post-MLP (old):** Gaussian noise in observation space — isotropic, doesn't follow manifold
- **Pre-MLP (new):** Perturbation in latent space → noise follows manifold curvature via MLP Jacobian

**Impact:** Changes the noise structure the model learns from. Pre-MLP noise is arguably more physically motivated but produces different training dynamics.

**Verdict:** 🔴 This is a conceptual change, not a bug fix. The old behavior should be restored for reproducibility, then the new behavior can be introduced as a separate experiment.

### 3b. RNG Sequence Desync from 10K Probe Set (`nd-kf-mlp`)

| Commit | File |
|---|---|
| `cf3ddcc` / `46d0c46` refactor chain | `dataset.py` |

**What changed:** New code calls `_sample_latents(10000, ...)` to estimate MLP output mean/std for z-normalization. This draws 10,000 × (k_shared + 2×m_unique) random values from `self.rng` **before** the actual data generation begins.

**Impact:** All subsequent `self.rng` draws (manifold latents, asymmetric noise, external noise) are shifted by 10K×(k+2m) positions in the numpy RNG stream. Even though the MLP weights are identical (controlled by `self.torch_rng`), the latent coordinates for every data point are different.

**Verdict:** 🔴 This is the same class of issue documented in the failnote. Even if the MLP architecture matches, the manifold data points are different → different training distribution → old checkpoints invalid.

---

### 3c. Garbage Generation RNG Switch (numpy → torch)

| Commit | File |
|---|---|
| Refactor chain | `dataset.py` |

**What changed:** Old code used `self.rng.rand(n, d_out)` (numpy RNG) for garbage point generation in `_generate_asym_corrupt` and `_generate_external`. New code uses `torch.rand(..., generator=self.torch_rng)`.

**Impact:** (a) Different RNG stream produces different garbage points. (b) `self.torch_rng` state is now consumed by garbage generation, shifting subsequent torch RNG draws (which were previously only used for MLP weight init). This means if multiple noise components are enabled, the torch RNG state diverges.

**Verdict:** 🟡 Only matters if noise rates > 0, which B13 configs may or may not have.

### 3d. Double Normalization in `nd-kf-mlp`

| Commit | File |
|---|---|
| Current code | `dataset.py` line 475-481 |

**What changed:** New code first normalizes MLP outputs using `norm_a/norm_b` (z-normalization with probe stats at line 426-427), then applies **another** in-place z-normalization at the end (lines 476-481). The old code had only one normalization pass.

**Impact:** Double normalization is idempotent **only** if the probe statistics perfectly match the actual data statistics. In practice, the 10K probe set statistics will differ from the N-sample actual data statistics (different random draws), creating a subtle bias. The second normalization should remove it, but this adds unnecessary complexity and changes the final data distribution compared to a single normalization pass.

**Verdict:** 🟡 Not a bug per se, but unnecessary. The second normalization compensates for the first being approximate.

### 4. `torch.compile` + AMP (mixed precision) in training loop

| Commit | File |
|---|---|
| `a8e87e2` (Jun 1) | `main.py` |
| `d853577` (Jun 3) | `main.py` (adds `dynamo.config.suppress_errors = True`) |

**What changed:**
- `torch.compile(dual_model)` — compiles the model graph
- AMP with `bfloat16` by default — changes numerical precision
- `GradScaler` — rescales gradients for mixed precision

**Impact:**
- `torch.compile` can alter gradient computation behavior for normalizing flows (log-det Jacobian is numerically sensitive)
- `bfloat16` has less precision than `float32` — Jacobian/log-det calculations may accumulate errors
- `suppress_errors = True` silently falls back to eager mode on compile failures — hides potential issues

**Verdict:** 🔴 `torch.compile` + AMP should be **opt-in config flags, defaulting to OFF** for safety. The `suppress_errors = True` is particularly dangerous — it hides compilation failures.

### 4b. Permutation `register_buffer` for torch.compile

| Commit | File |
|---|---|
| `a8e87e2` (Jun 1) | `ssl_disentangling.py` |

**What changed:** `_PermutationBase` permutation/inverse arrays changed from Python lists to `register_buffer` tensors. This was required for `torch.compile` compatibility.

**Impact:** (a) Functionally equivalent in eager mode. (b) State dict now includes `_permutation_tensor` / `_inverse_permutation_tensor` as buffers — old checkpoints won't have these keys, but `strict=False` loading would handle it. (c) Potential issue if old checkpoints are loaded with new code and strict loading is enabled.

**Verdict:** 🟡 Safe behavioral change, but **coupled to torch.compile** requirement. Should be kept.

### 5. Z-normalization of MLP outputs (SNR fix)

| Commit | File |
|---|---|
| Part of cf3ddcc / 46d0c46 refactor chain | `dataset.py` |

**What changed:** Added z-normalization (mean/std) for frozen MLP outputs **before** adding noise, using a 10,000-sample probe set. Old code did not normalize MLP outputs.

**Impact:** This is described as an "SNR collapse fix" — the claim is that without normalization, the MLP output std was ~1.0, making the manifold_noise_std of 0.02 essentially invisible. The z-normalization ensures consistent SNR.

**Verdict:** 🟡 This is arguably a **bug fix** (SNR was broken), but it changes data statistics from what B13 was trained on. Should be kept but needs to be validated as correct.

## 🎯 Recommended Recovery Strategy

> [!IMPORTANT]
> The failnote correctly diagnoses that RNG sequence changes make old checkpoints unrecoverable. The goal is NOT to make old checkpoints work with new code, but to ensure **new training runs produce correct results** with the refactored codebase.

### Phase 1: Restore data-generating process to match B13 semantics

These are the minimal changes to make the refactored code produce a dataset **statistically equivalent** to what B13 trained on (same distribution family, same noise model, even though exact RNG sequence differs):

1. **Revert `hidden_dim`** for `nd-kf-mlp` to 64 (line 396: `hidden_dim = 64` instead of `max(in_dim, self.d_out)`)
2. **Revert `hidden_dim`** for `3d-3f-2c-mlp` to 64 (line 218: remove `hidden_dim=D`)
3. **Revert noise model** to **post-MLP** for `nd-kf-mlp` — remove `noise_a`/`noise_b` from `_gen_mlp` calls, add post-MLP noise to outputs instead
4. **Remove double normalization** in `_init_nd_kf_mlp` — either keep probe-based normalization OR final in-place normalization, not both (keep the final one for simplicity)
5. **Disable `torch.compile` and AMP by default** — add `use_compile: false` and `use_amp: false` as config defaults

### Phase 2: Keep all safe changes (these don't alter data or training)
- ✅ All evaluation metric changes (RankMe, VICReg, CCA fix, statsmodels)
- ✅ VRAM-aware preloading + `set_training_mode()`
- ✅ Pre-allocated numpy arrays
- ✅ Chunked MLP processing
- ✅ Fixed eval set
- ✅ Normal distribution option (`shared_factor_dist`, opt-in)
- ✅ All visualization/notebook improvements
- ✅ Loss function robustness (`.strip().lower()`, control flow cleanup)
- ✅ Two-stage removal (dead code)
- ✅ `PointType` enum
- ✅ `FrozenRandomMLP` extraction (module-level class — as long as hidden_dim=64)
- ✅ `build_dataset_from_config()` helper
- ✅ Permutation `register_buffer` (torch.compile compat, functionally equivalent)
- ✅ All config/chore/docs

### Phase 3: Controlled re-introduction as explicit experiments
- Pre-MLP noise as **new config option** (e.g., `noise_location: pre_mlp | post_mlp`)
- `hidden_dim` as config parameter (e.g., `mlp_hidden_dim: 64`)
- `torch.compile` + AMP as opt-in flags (e.g., `use_compile: true`, `use_amp: true`)
- Z-normalization is already a positive change; keep it but make it the single normalization pass
